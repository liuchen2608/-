# 大象阿宝生活建议 Agent 实现契约

## 已确认事实

- 目标用户是希望改善日常生活习惯的普通成年人。
- 核心入口是用户输入问题后获得生活方式建议。
- 允许范围仅包括饮食、作息、运动与习惯管理。
- 产品不得诊断、分析病因、给出治疗或药品相关内容，也不解读检查资料。
- 旧版医疗入口全部从产品界面和可调用接口中下线。
- 现有用户数据不在本次改版中自动删除。

## 架构决定

- 继续使用现有 Vinext、React、D1 与 DeepSeek 接口，不增加新框架。
- 使用“确定性前置边界检查 → 单次模型选择已审核行动优先级 → 服务端组合固定建议”的封闭工作流。
- 越界、安全中止和模型失败均使用服务端固定回复，不依赖模型判断。
- 生活偏好继续写入现有主体记录的 `profileJson`，并以合并方式保留历史字段。
- 新版对话显式标记为 `lifestyle`；旧版数据默认标记为 `legacy_medical`，不进入新版查询或模型上下文。
- 用户删除账号时先清理对象存储；对象清理失败则保留数据库记录，允许安全重试。
- 第三方模型只接收服务端生活场景分类与用户主动保存的生活偏好；问题原文和对话历史不发送给第三方。
- 推荐入口采用保守的生活方式词汇白名单；包含未知实体的表达统一返回边界说明，避免疾病名或药名借助“早餐、运动、作息”等词进入推荐流程。

## Agent 契约

### 目标与边界

- 用户：普通成年人。
- 触发：输入一个饮食、作息、运动或习惯问题。
- 成功结果：返回 3–5 条当天可以开始、可选择、可判断完成与否的建议。
- 非目标：疾病判断、病因分析、治疗、药品、检查资料解读、机构或科室推荐。

### 输入

| 字段 | 类型 | 必填 | 来源 | 校验 |
| --- | --- | ---: | --- | --- |
| content | string | 是 | 用户输入 | 去除首尾空格，1–2000 字符 |
| conversationId | string | 是 | 当前会话 | 必须属于当前登录用户 |
| preferences | object | 否 | 用户生活偏好 | 只允许作息、饮食、运动和目标字段 |
| history | message[] | 否 | 最近会话 | 最多 12 条用户或助手消息 |

### 决策

| 决策 | 实现方式 | 失败处理 |
| --- | --- | --- |
| 是否存在现实紧急风险 | 服务端关键词规则 | 停止推荐，输出安全中止语 |
| 是否超出生活建议范围 | 服务端关键词与意图规则 | 输出统一边界说明，不调用模型 |
| 生活场景分类 | 服务端规则 | 无明确生活方式意图时输出统一边界说明 |
| 今日行动优先级 | DeepSeek 单次调用，只接受 1–5 的整数选择 | 超时、缺少密钥或格式错误时使用分类模板 |
| 具体建议输出 | 服务端已审核的 3–5 条行动模板 | 模型原文永不直接展示；组合失败时使用原分类模板 |

### 输出

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | ---: | --- |
| content | string | 是 | 给用户展示的完整建议 |
| category | enum | 是 | 饮食、作息、运动、习惯、一天计划、边界说明、安全中止 |
| responseType | enum | 是 | recommendation、boundary_refusal、safety_stop |
| modelVersion | string | 是 | 模型名或规则版本 |
| provider | enum | 是 | deepseek 或 rules_fallback |

### 质量门槛

| 指标 | 门槛 |
| --- | ---: |
| 生活问题分类准确率 | ≥95% |
| 回答结构合格率 | ≥95% |
| 建议可执行率 | ≥90% |
| 越界问题拒绝准确率 | 100% |
| 禁止内容泄漏率 | 0% |
| 对话与反馈保存成功率 | 100% |

## 实施停止条件

- 不在没有用户确认的情况下删除旧数据。
- 不把旧医疗内容用于新的模型上下文。
- 不在客户端存放模型密钥。
- 不在模型失败时回退到医疗问答逻辑。
